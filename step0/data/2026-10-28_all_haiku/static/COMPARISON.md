# Static layer rerun vs 2026-10-27

Generated by `node scripts/static-summary.mjs step0/skills.json step0/data/2026-10-28_all_haiku/static`
at `step0/skills.json` as pinned in commit `8d1e9ff`. No model calls, no cost.

## Result: no change

`SUMMARY.md` here is byte-identical to `step0/data/2026-10-27_static/SUMMARY.md` (checked with `diff`):
the same 18 skills, the same per-skill numbers, the same flags, the same four findings.

## Why it is identical

| Possible cause | Changed since 10-27? | Evidence |
|---|---|---|
| Skill versions (`ref` of any of the 18 skills) | No | `git diff 2bddadd HEAD -- step0/skills.json` touches only `lark-doc`, and only by adding `companions`; every `ref` and `subdir` is unchanged. Each cached clone's `HEAD` equals its pinned `ref`. |
| Check logic (`lib/static.js`) | No | `git diff 2c22e34 HEAD -- lib/static.js` is empty (2c22e34 is the last commit that touched the 10-27 output directory). |
| Summary script | No for the table | `scripts/static-summary.mjs` changed only to add the reader-poll section, which was already in the 10-27 output. |

So the rerun is a reproducibility confirmation, not a new measurement.

## Things this rerun does not cover

- **Companion skills.** `lark-doc` now installs `lark-drive` and `lark-shared` for trials (`companions` in `skills.json`),
  but the static layer analyzes only the pinned skill directory. The companions' tokens, code files and flags are not in
  this table. The lark-doc row is therefore the skill alone, not what the trial host actually loads.
- **Cache state.** The hyperframes clone has three deleted fixture files under `packages/studio-server/`, outside the
  skill's `subdir` (`skills/...`). They do not enter the analysis.

## Thresholds are uncalibrated

The cutoffs below were picked by hand and have not been calibrated against any distribution of real skills. Treat them as
ordering aids, not pass/fail bars.

- SKILL.md tokens: warn above 2,000, fail above 5,000 (check A1).
- Package size: warn above 2 MB (check A4).
- Finding 4 in `SUMMARY.md` ("exceed 1 MB") uses a separate 1 MB cutoff in the summary script, so it lists packages that
  check A4 does not flag.
