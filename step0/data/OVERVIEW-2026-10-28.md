# Step 0 overview: 18 popular skills, tested 2026-10-28

This page ties together four reports that measure different things. Read it to see which numbers mean what and which can be compared. Every number here is copied from one of the reports below, and each report counted its numbers from its own run data.

**These are automated test results.** The questions were drafted by AI and not reviewed by hand. The results describe how each skill triggered on the host, model and versions listed here; they are not an overall judgement of the skill's quality. If you think a question or a result is wrong, open an appeal in the repository (see "Appeals" in [CONTRIBUTING.md](../../CONTRIBUTING.md)).

## What can be compared

- **Haiku and DeepSeek can be compared** on the two question sets they share: same 36 sets, same host and CLI version, same verdict rule. Their tool lists and background skills differ slightly, and the DeepSeek report lists the differences. The comparison shows how a skill does on two models. It does not rank the models.
- **Codex has no trigger rate, by construction.** Codex does not record a skill call in its event stream, so no run can show whether a skill was used. The Codex report lists what each side did and rates nothing. Its rows cannot be set beside the Claude Code numbers.
- **The static layer does not depend on the host.** It reads declarations, not behaviour.

## Six things this step found

1. **Most skills trigger less than half the time when they should.** On Haiku, 11 of 18 skills fall under 50% recall, and recall across all skills is 41%. The result was 40% on DeepSeek as well.
2. **Explicit requests trigger; situations mostly do not.** A clause that names the skill's own job ("deploy my app to Vercel", "red-green-refactor") triggers far more often than a situation the skill should recognise ("push this live", "wants integration tests"). The pattern holds on both models.
3. **A grade depends on the model.** On the same questions, recall moved by more than 70 points between Haiku and DeepSeek (doc-coauthoring 12% → 85%, design-mobile-apps 83% → 32%). A skill does not have one trigger rate; it has one per host and model.
4. **A description can route work away, and the body cannot.** lark-doc's body sends copy requests to lark-drive, but its description does not, and two independently drafted copy requests went to lark-doc every time on Haiku. The model chooses a skill from the description alone.
5. **Who writes the test questions matters.** Each skill had two independently AI-drafted question sets. On Haiku, four skills' sets disagreed by up to 33 points. A third set settled their grades but not the gap. On DeepSeek, a different four skills disagreed.
6. **What the skills declare.** 17 of 18 declare no `allowed-tools`, 7 ship executable code, and skill-creator puts 8,368 tokens into the context every time it fires.

## Limits that apply to every number

- **False positives are measured with weak negatives.** Most should-not-trigger questions are far from the description. A low false-positive rate therefore does not show a tight boundary.
- **Questions are AI-drafted and were not reviewed by hand.** The independent question sets are the check, and the reports say where that check failed.
- **One host for trigger rates.** Claude Code was the host. Haiku is the headline model, and Sonnet, which users run more often, was not tested.
- **One machine's background skills.** Built-in skills can take a skill's triggers (for example, `run` took 8 of webapp-testing's), and that list differs between machines.
- **Strict verdict rule.** A model that looks at files first counts as a miss, as in skill-creator's own eval.
- **Small samples per skill.** 24–48 should-trigger queries per skill give wide intervals, and most rows sit close to a grade boundary.

node scripts/static-summary.mjs
